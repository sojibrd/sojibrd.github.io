# ০২ — রিজনিং টেকনিক

যেসব কাজে মডেলকে উত্তর দেওয়ার আগে ভাবতে হয়। মূল ধারণা এক জায়গায়: **উত্তরের আগে যুক্তি**।

## এই ক্যাটাগরিতে

| # | টেকনিক | এক লাইনে |
|---|---|---|
| ০১ | [Chain-of-Thought](01-chain-of-thought/) | ধাপে ধাপে চিন্তা করিয়ে তারপর উত্তর |
| ০২ | [Extended Thinking](02-extended-thinking/) | মডেলের বিল্ট-ইন চিন্তার বাজেট |
| ০৩ | [Self-consistency](03-self-consistency/) | একাধিক উত্তর নিয়ে সবচেয়ে বেশিবার আসাটা বাছা |
| ০৪ | [ReAct](04-react/) | চিন্তা ও টুল-কলের লুপ |
| ০৫ | [Tree of Thoughts](05-tree-of-thoughts/) | একাধিক শাখায় ভেবে সেরাটা বাছা |
| ০৬ | [Self-critique / Reflection](06-self-critique-reflection/) | নিজের আউটপুট নিজে রিভিউ করা |

## কোনটা কখন

| পরিস্থিতি | ব্যবহার করুন |
|---|---|
| হিসাব বা বহুধাপ যুক্তি | [Chain-of-Thought](01-chain-of-thought/) |
| জটিল ডিবাগিং, বড় পরিকল্পনা | [Extended Thinking](02-extended-thinking/) |
| উত্তর একটা নির্দিষ্ট মান, নির্ভুলতা জরুরি | [Self-consistency](03-self-consistency/) |
| বাইরের তথ্য লাগবে, কোনটা লাগবে জানা নেই | [ReAct](04-react/) |
| একাধিক বৈধ সমাধান আছে | [Tree of Thoughts](05-tree-of-thoughts/) |
| নির্দিষ্ট চেকলিস্ট মানতে হবে | [Self-critique](06-self-critique-reflection/) |

## খরচের হিসাব

এই টেকনিকগুলো সবই বাড়তি টোকেন খরচ করে, কিছু ক্ষেত্রে কয়েক গুণ:

```
Chain-of-Thought    → ~১.৫–২× আউটপুট টোকেন
Extended Thinking   → চিন্তার বাজেট অনুযায়ী
Self-consistency    → রান সংখ্যার সমান গুণ (৫ রান = ৫×)
Tree of Thoughts    → সবচেয়ে ব্যয়বহুল
Self-critique       → ~২× (দুই রাউন্ড)
```

তাই সহজ কাজে (শ্রেণিবিন্যাস, তথ্য নিষ্কাশন, সামারি) এগুলো ব্যবহার করবেন না — শুধু খরচ আর লেটেন্সি বাড়ে, মান বাড়ে না।

## এই স্তরের সাধারণ ভুল

- **উত্তর আগে, যুক্তি পরে** — মডেল তখন আন্দাজ করে, তারপর সেটার পক্ষে যুক্তি বানায়
- সব কাজে reasoning চালু রাখা
- যুক্তির অংশ আলাদা ট্যাগে না রাখা, ফলে ইউজারকে কাঁচা চিন্তা দেখানো
