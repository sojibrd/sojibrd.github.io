# ReAct (Reason + Act)

## সংজ্ঞা
চিন্তা → কাজ (টুল কল) → পর্যবেক্ষণ → আবার চিন্তা — এই লুপে মডেল ধাপে ধাপে এগোয়। আধুনিক এজেন্টের মূল কাঠামো।

## কখন ব্যবহার করবেন
- উত্তর দিতে বাইরের তথ্য লাগবে, আর কোন তথ্য লাগবে তা আগে থেকে জানা নেই
- একাধিক ধাপের কাজ, যেখানে পরের ধাপ আগের ফলাফলের উপর নির্ভরশীল

## লুপের চেহারা
```
ইউজার: "গত মাসে সবচেয়ে বেশি রিফান্ড হওয়া প্রোডাক্টটার স্টক কত?"

চিন্তা:      আগে গত মাসের রিফান্ড ডেটা লাগবে।
কাজ:         query_refunds(month="2026-07")
পর্যবেক্ষণ:  [{"product_id": "P-882", "count": 47}, ...]

চিন্তা:      P-882 সবার উপরে। এখন এর স্টক দেখতে হবে।
কাজ:         get_inventory(product_id="P-882")
পর্যবেক্ষণ:  {"stock": 12, "নাম": "ওয়্যারলেস ইয়ারবাড X2"}

চিন্তা:      দুটো তথ্যই পেয়েছি, এখন উত্তর দিতে পারি।
উত্তর:       গত মাসে সবচেয়ে বেশি রিফান্ড হয়েছে "ওয়্যারলেস ইয়ারবাড X2"
             (৪৭টি)। বর্তমানে স্টকে আছে ১২টি।
```

## উদাহরণ — সিস্টেম প্রম্পট
```
তোমার কাছে এই টুলগুলো আছে: query_refunds, get_inventory, create_ticket

প্রতিটা ধাপে:
- টুল কল করার আগে এক বাক্যে বলো কেন এই টুলটা দরকার
- একবারে একটা টুল কল করবে, ফলাফল দেখে পরেরটা ঠিক করবে
- তথ্য না পেলে অনুমান করবে না — বলবে কোন তথ্যটা পাওয়া যায়নি
- সর্বোচ্চ ৫টা টুল কলের মধ্যে শেষ করার চেষ্টা করবে
```

## মূল নিয়ম
- **লুপের সীমা বেঁধে দিন** — নাহলে মডেল একই টুল বারবার কল করতে থাকতে পারে
- টুলের error মেসেজ মডেলকে ফেরত দিন, সেটা থেকেই সে নিজেকে শোধরায়
- বিস্তারিত টুল ডিজাইনের জন্য দেখুন [Tool Use](../../03-system-patterns/03-tool-use/)
