# Self-critique / Reflection

## সংজ্ঞা
মডেল প্রথমে একটা আউটপুট দেয়, তারপর নির্দিষ্ট মানদণ্ড ধরে নিজের আউটপুট রিভিউ করে এবং সংশোধন করে।

## কখন ব্যবহার করবেন
- আউটপুটে নির্দিষ্ট নিয়ম মানতে হবে (স্টাইল গাইড, চেকলিস্ট)
- প্রথম খসড়ায় সাধারণত দু-একটা জিনিস বাদ পড়ে

## উদাহরণ — দুই ধাপে
```python
# ধাপ ১ — খসড়া
draft = ask("এই ফিচারের জন্য একটা রিলিজ নোট লেখো:\n" + feature_desc)

# ধাপ ২ — নিজের সমালোচনা ও সংশোধন
final = ask(f"""
নিচের রিলিজ নোটটা এই চেকলিস্ট ধরে যাচাই করো:

১. ইউজারের কী লাভ হলো, সেটা প্রথম বাক্যেই আছে কি?
২. কোনো ইন্টারনাল কোডনেম বা টিকিট নম্বর ঢুকে গেছে কি?
৩. ব্রেকিং চেঞ্জ থাকলে তা আলাদাভাবে চিহ্নিত আছে কি?
৪. ১৫০ শব্দের কম কি?

<সমালোচনা> ট্যাগে প্রতিটা পয়েন্টে পাস/ফেল লেখো।
তারপর <চূড়ান্ত> ট্যাগে সংশোধিত রিলিজ নোটটা দাও।

<খসড়া>
{draft}
</খসড়া>
""")
```

## মূল নিয়ম
- **সুনির্দিষ্ট চেকলিস্ট দিন** — "এটা ভালো করে দাও" বললে মডেল শুধু শব্দ বদলায়, ভুল ধরে না
- এক রাউন্ড রিফ্লেকশনেই বেশিরভাগ লাভ আসে; দ্বিতীয় রাউন্ডে খুব কম
- মডেল নিজের **তথ্যগত ভুল** নিজে ধরতে পারে না — সেজন্য বাইরের যাচাই লাগে, দেখুন [LLM-as-a-Judge](../../03-system-patterns/06-llm-as-a-judge/)
