# Context Engineering

## সংজ্ঞা
কনটেক্সট উইন্ডোতে কী ঢুকবে, কী ঢুকবে না, আর কোন ক্রমে ঢুকবে — তার পুরো ব্যবস্থাপনা। প্রম্পট ইঞ্জিনিয়ারিং একটা প্রম্পট নিয়ে ভাবে; কনটেক্সট ইঞ্জিনিয়ারিং পুরো উইন্ডোটা নিয়ে ভাবে।

## কখন ভাবতে হবে
- দীর্ঘ কথোপকথন বা এজেন্ট লুপ, যেখানে হিস্টরি বাড়তেই থাকে
- অনেক ডকুমেন্ট বা টুল-আউটপুট জমা হচ্ছে
- খরচ বা লেটেন্সি বাড়ছে, আর মান পড়ছে

## কনটেক্সটের ক্রম
```
১. System prompt          → স্থিতিশীল, ক্যাশযোগ্য
২. টুলের সংজ্ঞা            → স্থিতিশীল, ক্যাশযোগ্য
৩. রেফারেন্স ডকুমেন্ট      → আধা-স্থিতিশীল, ক্যাশযোগ্য
৪. কথোপকথনের হিস্টরি      → বাড়তে থাকে
৫. এই মুহূর্তের প্রশ্ন      → সবার শেষে
```
স্থিতিশীল জিনিস উপরে রাখলে [Prompt Caching](../05-prompt-caching/) কাজ করে।

## উদাহরণ — হিস্টরি ছাঁটাই
```python
def build_context(history, max_turns=10):
    if len(history) <= max_turns:
        return history

    # পুরনো অংশ সামারি করে একটা মেসেজে নামিয়ে আনুন
    old, recent = history[:-max_turns], history[-max_turns:]
    summary = ask("এই কথোপকথনের সিদ্ধান্ত ও তথ্যগুলো ৫টা বুলেটে লেখো:\n" + fmt(old))

    return [{"role": "user", "content": f"<আগের আলোচনার সারসংক্ষেপ>\n{summary}\n</আগের আলোচনার সারসংক্ষেপ>"}] + recent
```

## মূল নিয়ম
- **বেশি কনটেক্সট = ভালো ফলাফল, এটা ভুল ধারণা** — অপ্রাসঙ্গিক তথ্য মডেলকে বিভ্রান্ত করে
- টুল-আউটপুট কাঁচা অবস্থায় কনটেক্সটে ফেলবেন না; দরকারি অংশটুকু ছেঁকে নিন
