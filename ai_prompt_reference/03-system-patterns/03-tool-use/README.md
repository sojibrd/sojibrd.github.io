# Tool Use / Function Calling

## সংজ্ঞা
মডেলকে কিছু ফাংশনের বিবরণ দেওয়া হয়; সে ঠিক করে কখন কোনটা কল করতে হবে এবং কী আর্গুমেন্ট দিতে হবে। ফাংশনটা চালায় আপনার কোড, মডেল নয়।

## কখন ব্যবহার করবেন
- লাইভ ডেটা লাগবে (স্টক, অর্ডার স্ট্যাটাস, আবহাওয়া)
- বাস্তব কাজ করাতে হবে (টিকিট তৈরি, ইমেইল পাঠানো)
- নির্ভুল হিসাব দরকার — মডেলকে দিয়ে না করিয়ে ক্যালকুলেটর দিয়ে করান

## উদাহরণ
```python
tools = [{
    "name": "get_order_status",
    "description": (
        "অর্ডার আইডি দিয়ে অর্ডারের বর্তমান অবস্থা ও ডেলিভারির আনুমানিক তারিখ আনে। "
        "শুধু তখনই ব্যবহার করবে যখন ইউজার নির্দিষ্ট অর্ডার আইডি দিয়েছে। "
        "আইডি না থাকলে আগে ইউজারের কাছে চাইবে।"
    ),
    "input_schema": {
        "type": "object",
        "properties": {
            "order_id": {
                "type": "string",
                "description": "অর্ডার আইডি, ফরম্যাট: ORD-XXXXXX",
            }
        },
        "required": ["order_id"],
    },
}]

response = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=1024,
    tools=tools,
    messages=messages,
)
```

## মূল নিয়ম
- **`description`-ই আসল প্রম্পট** — টুলের নাম নয়, বিবরণ দেখেই মডেল সিদ্ধান্ত নেয়। কখন ব্যবহার করবে *এবং কখন করবে না*, দুটোই লিখুন
- টুলের সংখ্যা কম রাখুন; কাছাকাছি কাজের দুটো টুল থাকলে মডেল গুলিয়ে ফেলে
- error মেসেজ মডেলকে ফেরত দিন, লুকাবেন না — সে নিজেই শুধরে নেয়
- ধ্বংসাত্মক কাজে (ডিলিট, পেমেন্ট) মডেলের সিদ্ধান্তের উপর ভরসা না করে মানুষের অনুমোদন বসান, দেখুন [Guardrails](../07-guardrails/)
- লুপের কাঠামোর জন্য দেখুন [ReAct](../../02-reasoning-techniques/04-react/)
