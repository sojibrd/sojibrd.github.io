# LLM-as-a-Judge

## সংজ্ঞা
একটা মডেলের আউটপুট আরেকটা মডেল দিয়ে মূল্যায়ন করানো। যেখানে সঠিক উত্তর একটা নয়, সেখানে স্বয়ংক্রিয়ভাবে মান মাপার উপায়।

## কখন ব্যবহার করবেন
- আউটপুট লম্বা লেখা (সামারি, ইমেইল, ব্যাখ্যা) — স্ট্রিং মিলিয়ে যাচাই করা যায় না
- হাজারটা কেস মানুষ দিয়ে রিভিউ করা সম্ভব নয়

কখন **নয়**: আউটপুট যদি নির্দিষ্ট মান হয় (ক্যাটাগরি, সংখ্যা) — তখন সরাসরি মিলিয়ে দেখাই সঠিক ও সস্তা।

## উদাহরণ
```
তুমি একজন কড়া মূল্যায়নকারী। নিচের কাস্টমার সাপোর্ট উত্তরটা মূল্যায়ন করো।

<প্রশ্ন>{question}</প্রশ্ন>
<নথি>{source_docs}</নথি>
<উত্তর>{answer}</উত্তর>

প্রতিটা মানদণ্ডে ১–৫ স্কোর দাও:

১. তথ্যগত নির্ভুলতা — উত্তরের প্রতিটা দাবি কি নথিতে আছে?
   ৫ = সব দাবি নথিভিত্তিক | ৩ = একটা দাবি নথির বাইরে | ১ = বানানো তথ্য আছে
২. সম্পূর্ণতা — প্রশ্নের সব অংশের উত্তর আছে কি?
৩. টোন — ভদ্র কিন্তু অতিরিক্ত ক্ষমাপ্রার্থী নয়?

<মূল্যায়ন> ট্যাগে প্রতিটার স্কোর ও এক বাক্যে কারণ লেখো।
তারপর <রায়> ট্যাগে শুধু PASS বা FAIL — কোনো স্কোর ৩-এর নিচে হলে FAIL।
```

## মূল নিয়ম
- **স্কেলের প্রতিটা ধাপ সংজ্ঞায়িত করুন** — "১ থেকে ৫ দাও" বললে জাজ প্রায় সবসময় ৪ দেয়
- জাজকে **মূল নথি দিন**, নাহলে সে নির্ভুলতা যাচাই করতে পারবে না
- জাজকেও যাচাই করতে হয় — ২০টা কেসে মানুষের রায়ের সাথে মিলিয়ে দেখুন, দেখুন [Golden Dataset](../../04-evaluation/02-golden-dataset/)
- একই মডেল নিজের আউটপুট মূল্যায়ন করলে পক্ষপাত থাকে; সম্ভব হলে ভিন্ন মডেল ব্যবহার করুন
