# Response Prefilling

## সংজ্ঞা
অ্যাসিস্ট্যান্ট টার্নের শুরুটা আপনি নিজে লিখে দেন — মডেল সেখান থেকে বাকিটা লেখে। শুধু API-তে সম্ভব।

## কখন ব্যবহার করবেন
- আউটপুট JSON বা নির্দিষ্ট কাঠামোয় লাগবে, আর পার্সিং ভাঙা চলবে না
- মডেল বারবার ভূমিকা লিখে দিচ্ছে ("এই যে আপনার JSON:")
- উত্তর একটা নির্দিষ্ট ট্যাগ বা শব্দ দিয়ে শুরু হওয়া দরকার

কখন **নয়**: [Extended Thinking](../../02-reasoning-techniques/02-extended-thinking/) চালু থাকলে — তখন prefill সমর্থিত নয়।

## কেন কাজ করে
মডেলকে ফরম্যাট মানতে *অনুরোধ* করার চেয়ে ফরম্যাটের ভেতরে *ঢুকিয়ে দেওয়া* অনেক নির্ভরযোগ্য। ভূমিকা লেখার সুযোগই থাকে না।

## উদাহরণ — JSON বাধ্যতামূলক করা
```python
messages = [
    {"role": "user", "content": "এই রিভিউটার সেন্টিমেন্ট JSON-এ দাও: 'ডেলিভারি দেরি, প্রোডাক্ট ভালো'"},
    {"role": "assistant", "content": "{"}   # ← prefill
]
```
মডেল সরাসরি `"সেন্টিমেন্ট": "মিশ্র", ...}` দিয়ে শুরু করবে।
> মনে রাখবেন: শুরুর `{` আউটপুটে থাকবে না, তাই পার্স করার আগে সেটা জোড়া লাগাতে হবে।

## উদাহরণ — চিন্তার কাঠামো বেঁধে দেওয়া
```python
{"role": "assistant", "content": "<বিশ্লেষণ>\n১."}
```

## মূল নিয়ম
- prefill-এর শেষে অতিরিক্ত স্পেস বা নিউলাইন রাখবেন না
- extended thinking চালু থাকলে prefill সমর্থিত নয়
