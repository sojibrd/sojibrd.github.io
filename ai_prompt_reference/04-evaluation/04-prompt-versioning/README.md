# Prompt Versioning

## সংজ্ঞা
প্রম্পটকে কোডের মতো ট্রিট করা — ফাইলে রাখা, ভার্সন কন্ট্রোলে রাখা, প্রতিটা পরিবর্তনের সাথে কারণ ও eval ফলাফল রেকর্ড করা।

## কখন দরকার
প্রম্পট প্রোডাকশনে গেলেই। কোডের ভেতরে স্ট্রিং হিসেবে ছড়িয়ে থাকা প্রম্পট কয়েক সপ্তাহেই অব্যবস্থাপনায় পরিণত হয়।

## মূল নিয়ম
- প্রম্পট **কোড থেকে আলাদা ফাইলে** রাখুন — তাহলে diff পড়া যায়
- প্রতিটা ভার্সনের সাথে **কারণ ও eval ফলাফল** লিখুন, শুধু "উন্নত করা হলো" নয়
- মডেল ভার্সনও রেকর্ড করুন — একই প্রম্পট ভিন্ন মডেলে ভিন্ন আচরণ করে
- একবারে একটা জিনিস বদলান, নাহলে কোন পরিবর্তনে কী হলো বোঝা যাবে না
- সাথে দেখুন [Regression Testing](../03-regression-testing/)
