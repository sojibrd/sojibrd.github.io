# ০৪ — পরিমাপ ও মান নিয়ন্ত্রণ

মাপতে না পারলে প্রম্পট বদলানোটা ইঞ্জিনিয়ারিং নয়, অনুমান। এই ক্যাটাগরিটাই প্রম্পট নিয়ে খেলা আর প্রম্পট ইঞ্জিনিয়ারিংয়ের মধ্যে পার্থক্য।

## এই ক্যাটাগরিতে

| # | বিষয় | এক লাইনে |
|---|---|---|
| ০১ | [Evals](01-evals/) | টেস্ট সেট দিয়ে পারফরম্যান্স মাপা |
| ০২ | [Golden Dataset](02-golden-dataset/) | হাতে লেবেল করা রেফারেন্স কেস |
| ০৩ | [Regression Testing](03-regression-testing/) | প্রম্পট বদলালে আগের কেস ভাঙছে কিনা |
| ০৪ | [Prompt Versioning](04-prompt-versioning/) | প্রম্পটের ভার্সন ট্র্যাক করা |
| ০৫ | [Sampling Parameters](05-sampling-parameters/) | temperature, top-p ইত্যাদি |

## কাজের চক্র

```
[Golden Dataset তৈরি]  ← প্রম্পট লেখার আগেই, ৩০–১০০টা কেস
        ↓
[প্রম্পট লেখা]
        ↓
[Eval চালানো, temperature=0]
        ↓
[ব্যর্থ কেস দেখা]  ← স্কোরের চেয়ে এটাই বেশি দামি
        ↓
[প্রম্পট সংশোধন → নতুন ভার্সন + CHANGELOG]
        ↓
[Regression check: কী ঠিক হলো, কী ভাঙল]
        ↓
[প্রোডাকশন] → আসল ব্যর্থতা ধরে ডেটাসেটে ফেরত যোগ করুন
```

শেষ তীরটাই সবচেয়ে গুরুত্বপূর্ণ — প্রোডাকশনের ব্যর্থতা ডেটাসেটে ফিরিয়ে না আনলে eval সেট বাস্তবতা থেকে সরে যেতে থাকে।

## শুরু করার সবচেয়ে ছোট সংস্করণ

পুরো ব্যবস্থা একবারে দাঁড় করানোর দরকার নেই:

1. ২০টা কেস একটা `.jsonl` ফাইলে লিখুন
2. একটা লুপ যা সব কেস চালিয়ে সঠিকতা আর ব্যর্থ কেসের তালিকা দেয়
3. প্রম্পট আলাদা ফাইলে সরান, git-এ রাখুন

এইটুকুই ৮০% লাভ দেয়।

## এই স্তরের সাধারণ ভুল

- **মোট স্কোরের দিকে তাকিয়ে থাকা** — ৮২% → ৮৫% মানে হতে পারে ৫টা ঠিক হয়েছে, ২টা ভেঙেছে
- **eval `temperature=0`-তে না চালানো** — র‍্যান্ডমনেসকে উন্নতি ভেবে ভুল করবেন
- **যে কেস দেখে প্রম্পট বদলেছেন সেটা দিয়েই সাফল্য মাপা** — দেখুন [Overfitting](../05-failure-modes/04-overfitting-to-examples/)
- **সহজ কেস দিয়ে ডেটাসেট ভরে ফেলা** — যেসব কেসে আপনি নিজেই দ্বিধায় পড়েন, সেগুলোই আসল পরীক্ষা
