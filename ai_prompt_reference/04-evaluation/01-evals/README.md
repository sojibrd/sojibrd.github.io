# Evals

## সংজ্ঞা
একগুচ্ছ টেস্ট কেসের উপর প্রম্পট চালিয়ে ফলাফল মাপা। মাপতে না পারলে প্রম্পট বদলানোটা ইঞ্জিনিয়ারিং নয়, অনুমান।

## কখন ব্যবহার করবেন
সবসময় — প্রম্পট যদি প্রোডাকশনে যায়। ২০টা হাতে-লেখা কেসও শূন্যের চেয়ে অনেক ভালো।

## উদাহরণ
```python
CASES = [
    {"input": "পেমেন্ট কেটেছে কিন্তু অর্ডার নেই", "expected": "বিলিং"},
    {"input": "ডার্ক মোড কোথায়?",                "expected": "সাধারণ জিজ্ঞাসা"},
    {"input": "পাসওয়ার্ড রিসেট মেইল আসছে না",   "expected": "অ্যাকাউন্ট"},
    # ... এজ কেস, দ্ব্যর্থ কেস, খালি ইনপুট
]

def run_eval(prompt_version):
    results, failures = [], []
    for case in CASES:
        got = classify(case["input"], prompt=prompt_version)
        ok = got == case["expected"]
        results.append(ok)
        if not ok:
            failures.append({**case, "got": got})

    return {
        "সঠিকতা": sum(results) / len(results),
        "ব্যর্থ_কেস": failures,      # এটাই সবচেয়ে দামি অংশ
    }
```

## মূল নিয়ম
- **স্কোরের চেয়ে ব্যর্থ কেসের তালিকা বেশি দামি** — পরের প্রম্পট সংশোধন ওখান থেকেই আসে
- সহজ কেস দিয়ে ভরে ফেলবেন না; যেসব কেসে আপনি নিজেই দ্বিধায় পড়েন, সেগুলোই রাখুন
- প্রোডাকশনের আসল ব্যর্থতাগুলো ধরে ধরে eval সেটে যোগ করতে থাকুন
