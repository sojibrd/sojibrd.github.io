# Overfitting to Examples

## সংজ্ঞা
প্রম্পটটা যে কয়েকটা কেসে টেস্ট করা হয়েছে সেগুলোতে চমৎকার কাজ করে, কিন্তু বাস্তব ইনপুটে ভেঙে পড়ে।

## কখন দেখা যায়
- ৩টা কেস দেখে প্রম্পট টিউন করা, তারপর প্রোডাকশনে ছেড়ে দেওয়া
- few-shot উদাহরণে একই ধরনের কেস বারবার দেওয়া
- eval সেটে শুধু সহজ কেস রাখা

## লক্ষণ
```
eval সেটে সঠিকতা: ৯৬%
প্রোডাকশনে অভিযোগ: প্রতিদিন
```
এই ফারাকটাই সবচেয়ে বড় সংকেত — eval সেট বাস্তবতাকে প্রতিফলিত করছে না।

## প্রতিরোধ

few-shot-এ পক্ষপাত কীভাবে ঢোকে:
```
# সমস্যা: ৪টা উদাহরণের ৩টাই "উচ্চ" অগ্রাধিকার

টিকিট: "পেমেন্ট কেটেছে অর্ডার নেই"  → অগ্রাধিকার: উচ্চ
টিকিট: "লগইন হচ্ছে না"              → অগ্রাধিকার: উচ্চ
টিকিট: "সাইট খুলছে না"              → অগ্রাধিকার: উচ্চ
টিকিট: "ডার্ক মোড কোথায়?"           → অগ্রাধিকার: নিম্ন

# ফল: মডেল প্রায় সবকিছুকেই "উচ্চ" বলবে
```
সমাধান: উদাহরণে ক্লাসের ভারসাম্য রাখুন, আর সীমারেখার কেস রাখুন — যেমন এমন একটা কেস যেটা "মধ্যম"।

## মূল নিয়ম
- **টিউন করার সেট আর যাচাইয়ের সেট আলাদা রাখুন** — যে কেস দেখে প্রম্পট বদলেছেন, সেটা দিয়ে সাফল্য মাপবেন না
- few-shot উদাহরণে **ক্লাস ব্যালান্স** রাখুন
- প্রোডাকশনের আসল ইনপুট থেকে নিয়মিত নতুন কেস [Golden Dataset](../../04-evaluation/02-golden-dataset/)-এ যোগ করুন
- একটা কেস ঠিক করতে গিয়ে অন্যগুলো ভাঙছে কিনা দেখুন, দেখুন [Regression Testing](../../04-evaluation/03-regression-testing/)
