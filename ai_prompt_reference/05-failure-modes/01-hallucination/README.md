# Hallucination

## সংজ্ঞা
মডেল আত্মবিশ্বাসের সাথে ভুল বা বানানো তথ্য দেয় — অস্তিত্বহীন API, ভুল সংখ্যা, কাল্পনিক উদ্ধৃতি।

## কখন দেখা যায়
- প্রশ্নটা এমন তথ্য চায় যা মডেল জানে না (নতুন লাইব্রেরি, আপনার ইন্টারনাল সিস্টেম)
- প্রম্পটে "জানি না" বলার অনুমতি নেই
- নির্দিষ্ট সংখ্যা, তারিখ, নাম বা রেফারেন্স চাওয়া হয়েছে

## লক্ষণ
```
উত্তরটা সাবলীল, আত্মবিশ্বাসী, কিন্তু যাচাই করতে গেলে সূত্র মেলে না
```
সবচেয়ে বিপজ্জনক দিক: ভুল উত্তর আর সঠিক উত্তর দেখতে একদম একরকম।

দুর্বল প্রম্পটের উদাহরণ:
```
আমাদের রিফান্ড নীতি কী?
```
মডেল আপনার কোম্পানির নীতি জানে না, কিন্তু সাধারণ ই-কমার্স নীতি বানিয়ে দেবে — শুনতে একদম বিশ্বাসযোগ্য।

## প্রতিরোধ
```
<নীতি_নথি>
{{ আসল নীতির টেক্সট }}
</নীতি_নথি>

উপরের নথির ভিত্তিতে প্রশ্নের উত্তর দাও।

নিয়ম:
- প্রতিটা দাবির শেষে নথির সেকশন নম্বর দেবে, যেমন [ধারা ৪.২]
- নথিতে উত্তর না থাকলে ঠিক এই বাক্যটা লিখবে:
  "এই তথ্য আমাদের নীতিমালায় নেই, একজন এজেন্ট আপনাকে সাহায্য করবেন।"
- নথির বাইরে থেকে কোনো তথ্য যোগ করবে না, অনুমানও করবে না

প্রশ্ন: আমাদের রিফান্ড নীতি কী?
```

## মূল নিয়ম
- **"জানি না" বলার একটা নির্দিষ্ট বাক্য দিয়ে দিন** — শুধু "না জানলে বলো না" যথেষ্ট নয়
- সূত্র বাধ্যতামূলক করলে বানানো তথ্য অনেক কমে, দেখুন [RAG](../../03-system-patterns/02-rag/)
- তথ্য মডেলের স্মৃতি থেকে না এনে কনটেক্সটে দিন
- সংখ্যা বা হিসাব মডেলকে দিয়ে না করিয়ে [Tool Use](../../03-system-patterns/03-tool-use/) দিয়ে করান
- প্রম্পট দিয়ে পুরোপুরি বন্ধ হয় না — আউটপুট যাচাইয়ের স্তর লাগে, দেখুন [Guardrails](../../03-system-patterns/07-guardrails/)
