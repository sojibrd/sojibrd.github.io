০৫ — ফেইলিউর মোড

Lost in the Middle

সংজ্ঞা

লম্বা কনটেক্সটে মডেল শুরুর আর শেষের তথ্য ভালোভাবে ব্যবহার করে, কিন্তু মাঝখানের তথ্য তুলনামূলকভাবে উপেক্ষা করে।

কখন দেখা যায়

  • ২০+ নথি একসাথে RAG-এ দেওয়া হয়েছে
  • খুব লম্বা system prompt, যার মাঝখানে গুরুত্বপূর্ণ নিয়ম
  • লম্বা কথোপকথনের মাঝামাঝি বলা কোনো সিদ্ধান্ত মডেল ভুলে গেছে

লক্ষণ

"নথিতে তথ্যটা স্পষ্ট আছে, কিন্তু মডেল বলছে পায়নি"

নথিটা কনটেক্সটের কোথায় ছিল দেখুন — মাঝখানে হলে সম্ভবত এটাই কারণ।

প্রতিরোধ

# ১ — কম নথি দিন, কিন্তু প্রাসঙ্গিকতর
chunks = vector_search(q, top_k=5)          # ২০ নয়

# ২ — সবচেয়ে প্রাসঙ্গিক নথি শুরুতে ও শেষে রাখুন
# (নিজের হেল্পার — স্কোর অনুযায়ী সাজিয়ে প্রান্তে বসায়: [১ম, ৩য়, ৫ম, ৪র্থ, ২য়])
ordered = reorder_edges(chunks)

# ৩ — প্রতিটা নথিতে স্পষ্ট লেবেল দিন
context = "\n\n".join(f'<নথি id="{c.id}">\n{c.text}\n</নথি>' for c in ordered)

আর গুরুত্বপূর্ণ নির্দেশনা শেষে আবার মনে করিয়ে দিন:

<নথিসমূহ>...</নথিসমূহ>

মনে রাখো: উপরের প্রতিটা নথি পড়ে তবেই উত্তর দেবে,
এবং প্রতিটা দাবির সাথে নথির id দেবে।

প্রশ্ন: {question}

মূল নিয়ম

  • সবচেয়ে গুরুত্বপূর্ণ জিনিস শুরুতে বা শেষে রাখুন, মাঝে নয়
  • গুরুত্বপূর্ণ নির্দেশনা শেষে একবার পুনরাবৃত্তি করা সস্তা ও কার্যকর
  • বেশি নথি মানে ভালো উত্তর নয় — কম কিন্তু প্রাসঙ্গিক ভালো, দেখুন Context Engineering
  • সন্দেহ হলে পরীক্ষা করুন: একই নথি কনটেক্সটের ভিন্ন জায়গায় রেখে ফলাফল মিলিয়ে দেখুন
