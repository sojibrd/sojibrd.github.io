16:Tbac,## সংজ্ঞা
মডেলকে কিছু ফাংশনের বিবরণ দেওয়া হয়; সে ঠিক করে কখন কোনটা কল করতে হবে এবং কী আর্গুমেন্ট দিতে হবে। ফাংশনটা চালায় আপনার কোড, মডেল নয়।

## কখন ব্যবহার করবেন
- লাইভ ডেটা লাগবে (স্টক, অর্ডার স্ট্যাটাস, আবহাওয়া)
- বাস্তব কাজ করাতে হবে (টিকিট তৈরি, ইমেইল পাঠানো)
- নির্ভুল হিসাব দরকার — মডেলকে দিয়ে না করিয়ে ক্যালকুলেটর দিয়ে করান

## উদাহরণ
```python
tools = [{
    "name": "get_order_status",
    "description": (
        "অর্ডার আইডি দিয়ে অর্ডারের বর্তমান অবস্থা ও ডেলিভারির আনুমানিক তারিখ আনে। "
        "শুধু তখনই ব্যবহার করবে যখন ইউজার নির্দিষ্ট অর্ডার আইডি দিয়েছে। "
        "আইডি না থাকলে আগে ইউজারের কাছে চাইবে।"
    ),
    "input_schema": {
        "type": "object",
        "properties": {
            "order_id": {
                "type": "string",
                "description": "অর্ডার আইডি, ফরম্যাট: ORD-XXXXXX",
            }
        },
        "required": ["order_id"],
    },
}]

response = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=1024,
    tools=tools,
    messages=messages,
)
```

## মূল নিয়ম
- **`description`-ই আসল প্রম্পট** — টুলের নাম নয়, বিবরণ দেখেই মডেল সিদ্ধান্ত নেয়। কখন ব্যবহার করবে *এবং কখন করবে না*, দুটোই লিখুন
- টুলের সংখ্যা কম রাখুন; কাছাকাছি কাজের দুটো টুল থাকলে মডেল গুলিয়ে ফেলে
- error মেসেজ মডেলকে ফেরত দিন, লুকাবেন না — সে নিজেই শুধরে নেয়
- ধ্বংসাত্মক কাজে (ডিলিট, পেমেন্ট) মডেলের সিদ্ধান্তের উপর ভরসা না করে মানুষের অনুমোদন বসান, দেখুন [Guardrails](../07-guardrails/)
- লুপের কাঠামোর জন্য দেখুন [ReAct](../../02-reasoning-techniques/04-react/)19:Tb47,# RAG (Retrieval-Augmented Generation)

## সংজ্ঞা
প্রশ্নের সাথে প্রাসঙ্গিক ডকুমেন্ট খুঁজে বের করে সেটা প্রম্পটে যোগ করা, তারপর মডেলকে শুধু সেই তথ্যের ভিত্তিতে উত্তর দিতে বলা।

## কখন ব্যবহার করবেন
- উত্তর এমন তথ্যে নির্ভরশীল যা মডেলের ট্রেনিংয়ে ছিল না (আপনার কোম্পানির ডকুমেন্ট, সাম্প্রতিক ডেটা)
- তথ্য প্রায়ই বদলায়, তাই মডেলে ঢুকিয়ে রাখা যায় না
- উত্তরের সূত্র দেখাতে হবে

## উদাহরণ
```python
chunks = vector_search(user_question, top_k=5)

context = "\n\n".join(
    f'<নথি id="{c.id}" শিরোনাম="{c.title}">\n{c.text}\n</নথি>'
    for c in chunks
)

prompt = f"""<নথিসমূহ>
{context}
</নথিসমূহ>

<নির্দেশনা>
উপরের নথিগুলোর ভিত্তিতে প্রশ্নের উত্তর দাও।

- প্রতিটা দাবির শেষে সূত্র হিসেবে নথির id লিখবে, যেমন [doc-14]
- নথিতে উত্তর না থাকলে লিখবে: "প্রদত্ত নথিতে এই তথ্য নেই"
- নিজের সাধারণ জ্ঞান থেকে কিছু যোগ করবে না
</নির্দেশনা>

প্রশ্ন: {user_question}"""
```

## মূল নিয়ম
- **নথি আগে, প্রশ্ন পরে** — লং-কনটেক্সটে এই ক্রম মাপার মতো উন্নতি দেয়
- "উত্তর না জানলে বলবে জানি না" — এটা স্পষ্ট করে না বললে মডেল ফাঁক পূরণ করে দেয়, দেখুন [Hallucination](../../05-failure-modes/01-hallucination/)
- **সূত্র বাধ্যতামূলক করুন** — এতে যাচাই করা যায় এবং মডেলও নথিতে আটকে থাকে
- খারাপ retrieval-এর সমাধান প্রম্পটে নেই — ভুল নথি এলে সুন্দর প্রম্পটেও ভুল উত্তরই আসবে
- নথি স্থিতিশীল হলে [Prompt Caching](../05-prompt-caching/) দিয়ে খরচ অনেক কমে
1a:Tbe4,# Context Engineering

## সংজ্ঞা
কনটেক্সট উইন্ডোতে কী ঢুকবে, কী ঢুকবে না, আর কোন ক্রমে ঢুকবে — তার পুরো ব্যবস্থাপনা। প্রম্পট ইঞ্জিনিয়ারিং একটা প্রম্পট নিয়ে ভাবে; কনটেক্সট ইঞ্জিনিয়ারিং পুরো উইন্ডোটা নিয়ে ভাবে।

## কখন ভাবতে হবে
- দীর্ঘ কথোপকথন বা এজেন্ট লুপ, যেখানে হিস্টরি বাড়তেই থাকে
- অনেক ডকুমেন্ট বা টুল-আউটপুট জমা হচ্ছে
- খরচ বা লেটেন্সি বাড়ছে, আর মান পড়ছে

## কনটেক্সটের ক্রম
```
১. System prompt          → স্থিতিশীল, ক্যাশযোগ্য
২. টুলের সংজ্ঞা            → স্থিতিশীল, ক্যাশযোগ্য
৩. রেফারেন্স ডকুমেন্ট      → আধা-স্থিতিশীল, ক্যাশযোগ্য
৪. কথোপকথনের হিস্টরি      → বাড়তে থাকে
৫. এই মুহূর্তের প্রশ্ন      → সবার শেষে
```
স্থিতিশীল জিনিস উপরে রাখলে [Prompt Caching](../05-prompt-caching/) কাজ করে।

## উদাহরণ — হিস্টরি ছাঁটাই
```python
def build_context(history, max_turns=10):
    if len(history) <= max_turns:
        return history

    # পুরনো অংশ সামারি করে একটা মেসেজে নামিয়ে আনুন
    old, recent = history[:-max_turns], history[-max_turns:]
    summary = ask("এই কথোপকথনের সিদ্ধান্ত ও তথ্যগুলো ৫টা বুলেটে লেখো:\n" + fmt(old))

    return [{"role": "user", "content": f"<আগের আলোচনার সারসংক্ষেপ>\n{summary}\n</আগের আলোচনার সারসংক্ষেপ>"}] + recent
```

## মূল নিয়ম
- **বেশি কনটেক্সট = ভালো ফলাফল, এটা ভুল ধারণা** — অপ্রাসঙ্গিক তথ্য মডেলকে বিভ্রান্ত করে
