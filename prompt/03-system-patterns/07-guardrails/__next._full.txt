16:Te31,## সংজ্ঞা
মডেলের ইনপুট ও আউটপুটের চারপাশে বসানো যাচাইয়ের স্তর, যা অনাকাঙ্ক্ষিত জিনিস আটকায়। প্রম্পটে লেখা নিয়ম অনুরোধ; guardrail বাধ্যবাধকতা।

## কখন ব্যবহার করবেন
- সিস্টেমটা সাধারণ ব্যবহারকারীর হাতে খোলা
- এমন নিয়ম আছে যা ভাঙলে আইনি বা আর্থিক দায় আসে (রিফান্ড, চিকিৎসা, আইনি পরামর্শ)
- মডেলের হাতে টুল আছে, বিশেষত ধ্বংসাত্মক টুল

কার্যত: প্রোডাকশনে যাওয়া যেকোনো সিস্টেমে।

## কেন প্রম্পটই যথেষ্ট নয়
প্রম্পটে "কখনো রিফান্ডের নিশ্চয়তা দেবে না" লেখা থাকলেও যথেষ্ট চাপে মডেল সেটা ভাঙতে পারে। কোডে বসানো চেক ভাঙে না।

## তিনটা স্তর
```
১. ইনপুট guardrail   → মডেলে পাঠানোর আগে
২. প্রম্পট নির্দেশনা  → মডেলের ভেতরে (সবচেয়ে দুর্বল স্তর)
৩. আউটপুট guardrail  → ইউজারকে দেখানোর আগে
```

## উদাহরণ

> `contains_pii`, `cites_source`, `model_reply` — এগুলো আপনার নিজের লেখা ফাংশন, কোনো লাইব্রেরির নয়।

```python
def safe_reply(user_msg):
    # ১ — ইনপুট চেক
    if contains_pii(user_msg):
        return "নিরাপত্তার কারণে চ্যাটে কার্ড বা এনআইডি নম্বর দেবেন না।"

    raw = model_reply(user_msg)

    # ৩ — আউটপুট চেক
    if re.search(r"(রিফান্ড পাবেন|ফেরত নিশ্চিত)", raw):
        log.warning("policy_violation", extra={"reply": raw})
        return FALLBACK_REFUND_TEXT          # নিরাপদ, আগে থেকে লেখা উত্তর

    if not cites_source(raw) and mode == "rag":
        return "এই বিষয়ে নিশ্চিত তথ্য পাচ্ছি না, একজন এজেন্টের সাথে সংযোগ করিয়ে দিচ্ছি।"

    return raw
```

## মূল নিয়ম

- প্রতিটা লঙ্ঘন লগ করুন; ওই লগই পরের প্রম্পট উন্নতির সবচেয়ে ভালো ডেটা
- ধ্বংসাত্মক টুলে (ডিলিট, পেমেন্ট) মানুষের অনুমোদন বসান, দেখুন [Tool Use](../03-tool-use/)

## সংজ্ঞা
একটা মডেলের আউটপুট আরেকটা মডেল দিয়ে মূল্যায়ন করানো। যেখানে সঠিক উত্তর একটা নয়, সেখানে স্বয়ংক্রিয়ভাবে মান মাপার উপায়।

## কখন ব্যবহার করবেন
- আউটপুট লম্বা লেখা (সামারি, ইমেইল, ব্যাখ্যা) — স্ট্রিং মিলিয়ে যাচাই করা যায় না
- হাজারটা কেস মানুষ দিয়ে রিভিউ করা সম্ভব নয়

কখন **নয়**: আউটপুট যদি নির্দিষ্ট মান হয় (ক্যাটাগরি, সংখ্যা) — তখন সরাসরি মিলিয়ে দেখাই সঠিক ও সস্তা।
