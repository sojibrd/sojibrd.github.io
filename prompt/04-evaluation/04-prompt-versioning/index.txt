## মূল নিয়ম
- প্রম্পট **কোড থেকে আলাদা ফাইলে** রাখুন — তাহলে diff পড়া যায়
- প্রতিটা ভার্সনের সাথে **কারণ ও eval ফলাফল** লিখুন, শুধু "উন্নত করা হলো" নয়
- মডেল ভার্সনও রেকর্ড করুন — একই প্রম্পট ভিন্ন মডেলে ভিন্ন আচরণ করে
- একবারে একটা জিনিস বদলান, নাহলে কোন পরিবর্তনে কী হলো বোঝা যাবে না
- সাথে দেখুন [Regression Testing](../03-regression-testing/)19:Ta42,# Regression Testing

## সংজ্ঞা
প্রম্পট বা মডেল বদলানোর পর আগের যেসব কেস ঠিক ছিল, সেগুলো এখনো ঠিক আছে কিনা যাচাই করা।

## কখন চালাবেন
- প্রম্পটে যেকোনো পরিবর্তনের পর
- মডেল ভার্সন আপগ্রেড করলে
- টুল বা RAG-এর নথি বদলালে

## কেন দরকার
প্রম্পট ইঞ্জিনিয়ারিংয়ের সবচেয়ে সাধারণ ফাঁদ: একটা কেস ঠিক করতে গিয়ে তিনটা ভেঙে ফেলা। মডেল ডিটারমিনিস্টিক নয়, তাই "ছোট পরিবর্তন" বলে কিছু নেই।

## উদাহরণ
```python
def compare(old_prompt, new_prompt, cases):
    fixed, broken, unchanged = [], [], 0

    for c in cases:
        old_ok = classify(c["input"], old_prompt) == c["expected"]
        new_ok = classify(c["input"], new_prompt) == c["expected"]

        if not old_ok and new_ok:
            fixed.append(c["id"])
        elif old_ok and not new_ok:
            broken.append(c["id"])       # ← এটাই regression
        else:
            unchanged += 1

    return {"ঠিক_হয়েছে": fixed, "ভেঙেছে": broken, "অপরিবর্তিত": unchanged}
```

আউটপুট দেখতে হবে এভাবে:
```
ঠিক_হয়েছে: ['t-014', 't-031']
ভেঙেছে:    ['t-007']          ← মোট স্কোর বাড়লেও এটা আগে দেখুন
```

## মূল নিয়ম
- **মোট স্কোরের দিকে তাকিয়ে থাকবেন না** — ৮২% থেকে ৮৫% হওয়ার মানে হতে পারে ৫টা ঠিক হয়েছে আর ২টা ভেঙেছে
- ভাঙা কেসগুলো আলাদা করে দেখুন; কোনটা গ্রহণযোগ্য আর কোনটা নয়, সেটা মানুষের সিদ্ধান্ত
- `temperature=0` রাখুন, নাহলে র‍্যান্ডমনেসকে regression ভেবে ভুল করবেন
- CI-তে বসিয়ে দিন — প্রম্পট ফাইল বদলালেই যেন চলে

## সংজ্ঞা
মডেল পরের টোকেন কীভাবে বাছবে তা নিয়ন্ত্রণকারী প্যারামিটার — মূলত `temperature`, `top_p`, `max_tokens`, `stop_sequences`।

## কখন ব্যবহার করবেন
- আউটপুট প্রতিবার একই লাগবে (eval, শ্রেণিবিন্যাস, তথ্য নিষ্কাশন) → `temperature=0`
- আউটপুটে ভিন্নতা লাগবে (আইডিয়া, কপি, [Self-consistency](../../02-reasoning-techniques/03-self-consistency/)) → বেশি temperature
- আউটপুট নির্দিষ্ট জায়গায় থামাতে হবে → `stop_sequences`

ডিফল্ট নিয়ম: সন্দেহ হলে `temperature=0` রাখুন, `top_p`-তে হাত দেবেন না।

## কোনটা কখন
| প্যারামিটার | কাজ | কখন বদলাবেন |
|---|---|---|
| `temperature` | এলোমেলো ভাব (০–১) | নির্ভুলতা চাইলে ০, সৃজনশীলতা চাইলে ০.৭–১ |
| `top_p` | সম্ভাব্য টোকেনের পুল ছাঁটাই | সাধারণত হাত দেবেন না |
| `max_tokens` | আউটপুটের সর্বোচ্চ দৈর্ঘ্য | খরচ ও কাটা-পড়া নিয়ন্ত্রণে |
| `stop_sequences` | নির্দিষ্ট টেক্সট এলে থেমে যাওয়া | কাঠামোবদ্ধ আউটপুট কাটতে |

## কাজভিত্তিক সেটিং
```python
# শ্রেণিবিন্যাস, তথ্য নিষ্কাশন, eval — একই ইনপুটে একই আউটপুট চাই
temperature=0

# সাপোর্ট উত্তর, সামারি — সামান্য স্বাভাবিকতা
temperature=0.3

# মার্কেটিং কপি, আইডিয়া জেনারেশন
temperature=0.8

# Self-consistency — ভিন্নতা না থাকলে কৌশলটাই অর্থহীন
temperature=1.0
```

## মূল নিয়ম
- `temperature` আর `top_p` একসাথে বদলাবেন না — একটা বেছে নিন
- **eval সবসময় `temperature=0`-তে চালান**, নাহলে র‍্যান্ডমনেসকে উন্নতি বা [regression](../03-regression-testing/) ভেবে ভুল করবেন
